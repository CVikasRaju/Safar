# 18 — Implementation Roadmap

## Phase 0 — Inspect before editing
- Inspect repository, package manager, existing stack, scripts, and current errors.
- Summarise findings.
- Preserve working code.
- Identify environment constraints.

## Phase 1 — Foundation
- App shell, responsive sidebar, workspace switch.
- Typed domain model.
- Seed data and referential validation.
- Shared state and LocalStorage.
- Basic dashboard and navigation.

## Phase 2 — Journey planner
- Search inputs.
- Candidate generation.
- Three independent rankings.
- Detailed segment timeline.
- Honest map/schematic fallback.
- Reliability.

## Phase 3 — Immediate disruption
- Student report form.
- Unverified report queue.
- Authority verify/reject/duplicate.
- Separate incident confirmation.
- Affected journeys and alerts.

## Phase 4 — Fleet response
- Fleet status.
- Candidate eligibility.
- Weighted replacement ranking.
- No-solution state.
- Alternative connections.
- Approval/rejection and state propagation.

## Phase 5 — Event intelligence
- Event CRUD.
- Impact calculation.
- Advance warnings.
- Affected routes/journeys.
- AI extraction only after deterministic path works.

## Phase 6 — Demand and analytics
- Seed totals.
- Student travel submissions.
- Aggregation.
- Charts and shortage analysis.

## Phase 7 — Scenarios and AI
- Central scenario.
- Isolated breakdown scenario.
- Reset.
- Provider adapter and fallback.
- AI grounded explanations.

## Phase 8 — Validation
- Unit/integration tests.
- Responsive review.
- Build and console checks.
- Persistence/reset.
- Demo rehearsal.

## Two-hour prototype priority
If time is extremely limited, complete the working foundation, journey planner, student report, authority verification/incident confirmation, replacement approval, and shared-state propagation before polishing optional AI or maps. Simplify visual complexity, not the core workflow.
